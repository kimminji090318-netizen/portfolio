# 딱맞뷰티 2.0

> 기존 딱맞뷰티 프로젝트와 분리해 진행하는 개선·실험 기록입니다.  
> 이 폴더는 신규 기록용이며, 저장소에 있던 기존 딱맞뷰티 파일은 수정하거나 삭제하지 않습니다.

## 1. 업그레이드를 시작한 이유

- 포트폴리오를 정리하던 중 기존 코드와 PRD(Product Requirements Document)의 내용이 서로 일치하지 않는 부분을 발견했습니다.
- 기존 구현을 그대로 유지하기보다, 데이터 처리 과정과 진단 로직을 직접 점검하고 개선하고 싶었습니다.
- 기존 데이터 외에 약 5천 건 규모의 데이터를 추가해 분석을 확장해 보고 싶은 목표가 있습니다.
- 데이터 분석과 서비스 개선 과정을 직접 설계하고 구현하는 활동에 흥미가 있어 이번 업그레이드를 시작했습니다.

## 2. 2026-11-10(화) 작업 기록

### 기존 프로젝트 및 데이터 검토
- 기존 진단 코드와 PRD의 차이를 확인하고, 데이터 처리·진단 과정을 새로 검토하기로 했습니다.
- 기존 코드가 RGB를 Lab으로 변환하고 이미지 중앙 일부의 평균 색상을 이용하는 단순 규칙 기반 구조임을 확인했습니다.
- 실제 피부 영역 검출, 학습된 분류 모델, 전문가 정답 라벨을 이용한 검증은 기존 구현에 포함되어 있지 않음을 정리했습니다.
- 기존 피부 측정 데이터 92명의 Lab 값을 살펴보고, 교차 편광과 화이트 라이트 조건의 측정 차이 및 변수 간 관계를 검토했습니다.
- 웹앱 카메라 촬영으로 얻은 실제 테스트 로그 13건을 확인했습니다. 이 로그는 앱 실행 결과이며 전문가가 판정한 정답 라벨은 아니므로 진단 정확도 평가 자료로 간주하지 않기로 했습니다.
- 기존 계절별 Lab 범위는 검증된 정답 기준이 아니라 기존 프로젝트에서 사용하던 설정값으로 구분했습니다.

### 새 분석용 웹앱 프로토타입 구성
- 기존 시스템을 바로 덮어쓰지 않고, 별도의 React 프런트엔드와 Python FastAPI 백엔드 기반 프로토타입을 준비했습니다.
- 대시보드, 데이터 분석, 클러스터링, 진단 기준 관리, 이미지 Lab 추출 실험 화면을 구성했습니다.
- CSV 업로드 및 Lab 통계 확인, K-means와 Ward 계층적 군집화, PCA 시각화, 군집별 평균 Lab 확인 기능을 포함했습니다.
- 이미지 진단 화면은 현재 피부 검출이 아니라 이미지 중앙 일부의 색상값을 추출하는 실험 기능임을 명시했습니다.

### 개발환경 설정 및 실행
- Windows + VS Code + Anaconda 환경에서 Python 3.12.7의 base 환경을 사용하도록 설정했습니다.
- FastAPI, Uvicorn, python-multipart를 설치하고 백엔드 서버 실행을 확인했습니다.
- 프런트엔드 의존성을 설치하고 Vite 개발 서버 실행을 확인했습니다.
- PowerShell의 스크립트 실행 정책으로 `npm.ps1` 실행이 제한되는 문제는 `npm.cmd` 명령으로 우회했습니다.
- React 리스트 렌더링에서 발생한 고유 `key` 경고를 수정했습니다.
- 브라우저에서 기본 화면이 오류 없이 작동하는 것을 확인했습니다.
- favicon 404는 기능과 무관한 아이콘 파일 누락 알림으로 확인해 후순위로 두었습니다.

## 3. 2026-11-24(화) 작업 기록

### 데이터 분석 및 군집 모델
- 기존 92명 피부 측정 데이터와 기업 데이터 3,439건을 구분해 분석했습니다. 통합 유효 Lab 데이터는 3,531건입니다.
- L*, a*, b*를 이용한 StandardScaler + K-means 군집 비교 결과를 재사용·검토했습니다.
- 기업 데이터 단독 K=3 모델을 후보 모델로 선택했습니다. 학습 설정은 `random_state=42`, `n_init=50`이며 silhouette score는 약 0.3283719입니다.
- 학습된 K-means 모델과 StandardScaler를 joblib 파일로 저장했습니다. 신규 이미지 예측에는 학습된 scaler의 `transform()`과 모델의 `predict()`를 사용하며, 단일 이미지로 scaler를 다시 학습하지 않습니다.
- 모델 메타데이터에 입력 데이터 해시, 변수 순서, scaler 파라미터, 군집 중심 및 진단 미검증 후보 상태를 기록했습니다.
- 군집 번호는 탐색적 그룹 식별자이며 봄·여름·가을·겨울 퍼스널 컬러 정답으로 해석하지 않습니다.

### 조명 차이 조사 및 보정 구조
- 기존 92명 데이터에서 이름을 기준으로 백색 라이트와 교차 편광 Lab 값 92쌍을 대응했습니다. 개인 식별 정보는 결과 보고서에 포함하지 않았습니다.
- 백색 라이트 − 교차 편광 평균 차이는 L* -1.460, a* +0.889, b* -1.778이며 표준편차는 각각 1.048, 0.577, 0.625입니다.
- 이 값은 기존 측정 시스템 간 차이이므로 스마트폰 카메라의 조명 보정값으로 사용하지 않았습니다.
- 카메라 기종·노출·화이트밸런스를 통제한 짝지은 촬영 데이터가 아직 없어 실제 카메라 보정은 비활성화했습니다. 보정 레지스트리는 구조만 만들고 비워 두었습니다.
- 프런트엔드에서 백색등·자연광 등 촬영 조명을 선택하고, 백엔드에서 해당 조건의 보정값이 존재할 때만 보정하도록 연결했습니다. 보정값이 없으면 원본 Lab을 그대로 반환합니다.

### 이미지 분석 API 및 프런트엔드 연결
- FastAPI 이미지 분석 API에 저장된 모델과 scaler를 연결했습니다.
- API는 원본 Lab, 보정 Lab, 선택 조명, 보정 적용 여부, 예측 군집 및 군집 중심 Lab을 반환합니다.
- 프런트엔드에서 촬영 조명 선택, 카메라 촬영 결과, Lab 값, 군집 번호 및 주의 안내를 표시하도록 연결했습니다.
- 잘못된 조명 조건, 업로드 형식, 얼굴 미검출, 모델 누락 등 오류 응답을 테스트했습니다.
- 합성 이미지와 얼굴 검출 대역 객체를 사용한 통합 스모크 테스트에서 모델 로딩, 반복 예측 일치, 보정 산식, 기존 health 및 cluster API 보존을 확인했습니다.
- `npm.cmd run build`가 성공했습니다. 다만 Vite 번들 크기 500KB 초과 경고와 테스트 도구 deprecation 경고가 남아 있습니다.

### 실제 브라우저 카메라 테스트
- 로컬 FastAPI 서버(`127.0.0.1:8000))와 Vite 프런트엔드(`localhost:5173))를 실행했습니다.
- 브라우저에서 실제 카메라 촬영, 이미지 업로드 분석, Lab 표시, 군집 예측 결과 표시까지 확인했습니다.
- 백색등으로 선택한 촬영 결과: 피부 픽셀 9,311개, L* 62.39 / a* 5.91 / b* 16.34, 탐색 군집 2.
- 야간에 조명 선택을 자연광으로 둔 상태에서 반복 촬영한 결과:
  - 1회차: 피부 픽셀 8,707개, L* 57.88 / a* 6.92 / b* 16.19
  - 2회차: 피부 픽셀 9,284개, L* 58.04 / a* 6.02 / b* 16.33
  - 3회차: 피부 픽셀 9,403개, L* 56.94 / a* 6.94 / b* 16.48
  - 세 번 모두 탐색 군집 2로 분류됐습니다.
- 위 세 번은 야간 촬영이므로 실제 자연광 측정으로 간주할 수 없습니다. 조명 선택값과 실제 광원 조건을 구분해 기록해야 합니다.
- 백색등 결과와 야간 실내 촬영 결과는 광원 조건이 통제되지 않았으므로 조명별 보정값 계산이나 자연광 대비 분석에 사용하지 않습니다.
- API 문서와 서버 상태 확인은 정상입니다. 브라우저가 백엔드 루트 `GET /`에 접근해 404가 기록된 것은 루트 페이지 미등록에 따른 응답이며, 실제 API 오류와 구분했습니다.

4. 브라우저 카메라 권한, 재촬영, 이미지 업로드, 분석 결과 표시를 실제 기기에서 다시 확인합니다.

7. 번들 크기 경고와 테스트 도구 deprecation 경고를 검토하되, 기능 안정성을 해치지 않는 범위에서 처리합니다.
8. Gemini 설명 기능과 Google Sheets 저장 연동은 핵심 분석 흐름 안정화 이후 진행합니다.

## 5. 개발 원칙

- **기존 프로젝트 보호:** 기존 딱맞뷰티 파일은 임의로 수정·삭제·덮어쓰지 않습니다. 2.0 작업은 별도 폴더와 별도 구현에서 진행합니다.
- **데이터 출처 구분:** 실제 측정 데이터, 앱 테스트 로그, 가상·합성 데이터를 명확히 구분합니다.
- **라벨 품질 우선:** 앱이 자동으로 출력한 계절 결과를 전문가 정답 라벨처럼 사용하지 않습니다.
- **측정과 분류 분리:** 조명·카메라·촬영 위치에 따른 측정 오차와 분류 알고리즘의 오차를 구분합니다.
- **검증 가능한 분석:** 전처리 과정, 분석 방법, 기준값, 평가 결과를 기록해 재현할 수 있도록 합니다.
- **군집 해석 주의:** 클러스터링은 유사한 데이터의 그룹을 찾는 탐색 기법이며, 군집 번호를 봄·여름·가을·겨울의 정답으로 바로 치환하지 않습니다.
- **성능 과장 금지:** 전문가 정답 라벨과 적절한 검증 절차가 없으면 진단 정확도를 주장하지 않습니다.
- **단계적 개선:** 원본 데이터와 기존 기능을 보존하고, 새 기능은 작은 단위로 구현·검증한 뒤 확장합니다.

# 딱맞뷰티 2.0

> 기존 딱맞뷰티 프로젝트와 분리해 진행하는 개선·실험 기록입니다.  
> 이 폴더는 신규 기록용이며, 저장소에 있던 기존 딱맞뷰티 파일은 수정하거나 삭제하지 않습니다.

## 1. 업그레이드를 시작한 이유

- 포트폴리오를 정리하던 중 기존 코드와 PRD(Product Requirements Document)의 내용이 서로 일치하지 않는 부분을 발견했습니다.
- 기존 구현을 그대로 유지하기보다, 데이터 처리 과정과 진단 로직을 직접 점검하고 개선하고 싶었습니다.
- 기존 데이터 외에 약 5천 건 규모의 데이터를 추가해 분석을 확장해 보고 싶은 목표가 있습니다.
- 데이터 분석과 서비스 개선 과정을 직접 설계하고 구현하는 활동에 흥미가 있어 이번 업그레이드를 시작했습니다.

## 2. 2026-11-10(화) 작업 기록

### 기존 프로젝트 및 데이터 검토
- 기존 진단 코드와 PRD의 차이를 확인하고, 데이터 처리·진단 과정을 새로 검토하기로 했습니다.
- 기존 코드가 RGB를 Lab으로 변환하고 이미지 중앙 일부의 평균 색상을 이용하는 단순 규칙 기반 구조임을 확인했습니다.
- 실제 피부 영역 검출, 학습된 분류 모델, 전문가 정답 라벨을 이용한 검증은 기존 구현에 포함되어 있지 않음을 정리했습니다.
- 기존 피부 측정 데이터 92명의 Lab 값을 살펴보고, 교차 편광과 화이트 라이트 조건의 측정 차이 및 변수 간 관계를 검토했습니다.
- 웹앱 카메라 촬영으로 얻은 실제 테스트 로그 13건을 확인했습니다. 이 로그는 앱 실행 결과이며 전문가가 판정한 정답 라벨은 아니므로 진단 정확도 평가 자료로 간주하지 않기로 했습니다.
- 기존 계절별 Lab 범위는 검증된 정답 기준이 아니라 기존 프로젝트에서 사용하던 설정값으로 구분했습니다.

### 새 분석용 웹앱 프로토타입 구성
- 기존 시스템을 바로 덮어쓰지 않고, 별도의 React 프런트엔드와 Python FastAPI 백엔드 기반 프로토타입을 준비했습니다.
- 대시보드, 데이터 분석, 클러스터링, 진단 기준 관리, 이미지 Lab 추출 실험 화면을 구성했습니다.
- CSV 업로드 및 Lab 통계 확인, K-means와 Ward 계층적 군집화, PCA 시각화, 군집별 평균 Lab 확인 기능을 포함했습니다.
- 이미지 진단 화면은 현재 피부 검출이 아니라 이미지 중앙 일부의 색상값을 추출하는 실험 기능임을 명시했습니다.

### 개발환경 설정 및 실행
- Windows + VS Code + Anaconda 환경에서 Python 3.12.7의 base 환경을 사용하도록 설정했습니다.
- FastAPI, Uvicorn, python-multipart를 설치하고 백엔드 서버 실행을 확인했습니다.
- 프런트엔드 의존성을 설치하고 Vite 개발 서버 실행을 확인했습니다.
- PowerShell의 스크립트 실행 정책으로 `npm.ps1` 실행이 제한되는 문제는 `npm.cmd` 명령으로 우회했습니다.
- React 리스트 렌더링에서 발생한 고유 `key` 경고를 수정했습니다.
- 브라우저에서 기본 화면이 오류 없이 작동하는 것을 확인했습니다.
- favicon 404는 기능과 무관한 아이콘 파일 누락 알림으로 확인해 후순위로 두었습니다.

## 3. 다음 작업

2. 업로드된 데이터의 행 수, 결측값, 중복, Lab 값 범위 및 통계를 원본과 대조합니다.
3. 교차 편광과 화이트 라이트 측정값을 구분해 분석하고, 조명 조건에 따른 차이를 검토합니다.
4. K-means와 Ward 계층적 군집화 결과를 비교하고, 군집 수에 따른 안정성과 해석 가능성을 확인합니다.
5. PCA 및 군집별 Lab 평균 시각화를 개선합니다.
6. 추가 데이터 약 5천 건을 확보할 경우 출처, 측정 조건, 중복 여부, 라벨 품질을 먼저 확인한 뒤 통합합니다.
7. 실제 전문가 판정 라벨을 확보할 수 있는지 검토하고, 확보 후에만 계절 진단 성능을 별도로 평가합니다.
8. 데이터 분석 결과를 바탕으로 진단 기준과 분류 알고리즘을 재설계합니다.

## 4. 개발 원칙

- **기존 프로젝트 보호:** 기존 딱맞뷰티 파일은 임의로 수정·삭제·덮어쓰지 않습니다. 2.0 작업은 별도 폴더와 별도 구현에서 진행합니다.
- **데이터 출처 구분:** 실제 측정 데이터, 앱 테스트 로그, 가상·합성 데이터를 명확히 구분합니다.
- **라벨 품질 우선:** 앱이 자동으로 출력한 계절 결과를 전문가 정답 라벨처럼 사용하지 않습니다.
- **측정과 분류 분리:** 조명·카메라·촬영 위치에 따른 측정 오차와 분류 알고리즘의 오차를 구분합니다.
- **검증 가능한 분석:** 전처리 과정, 분석 방법, 기준값, 평가 결과를 기록해 재현할 수 있도록 합니다.
- **군집 해석 주의:** 클러스터링은 유사한 데이터의 그룹을 찾는 탐색 기법이며, 군집 번호를 봄·여름·가을·겨울의 정답으로 바로 치환하지 않습니다.
- **단계적 개선:** 원본 데이터와 기존 기능을 보존하고, 새 기능은 작은 단위로 구현·검증한 뒤 확장합니다.
- **성능 과장 금지:** 전문가 정답 라벨과 적절한 검증 절차가 없으면 진단 정확도를 주장하지 않습니다.
